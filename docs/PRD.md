## 一、产品定位

轻量级 Mac **纯原生** (Swift + SwiftUI) 自动化工具，核心实现：
- 飞书多维表格数据读取
- 多抖音账号管理
- 抖音作品自动发布（headless，无浏览器界面）

**兼容性要求**：Universal Binary（Intel + M 系列），macOS 13.0+（Ventura）。

> 为什么 macOS 13+：`NavigationSplitView`（侧边栏+内容区标准布局）从 macOS 13 开始可用。macOS 12 的 `NavigationView` 行为不稳定且已被 Apple 废弃。macOS 13+ 覆盖 2017 年及之后的所有 Mac，用户覆盖率极高。

### 2.1 飞书多维表格配置（支持多配置管理）

- 支持用户添加、编辑、删除多个飞书多维表格配置，快速切换
- 配置项：
  - 配置名称（用户自定义，便于识别）
  - **飞书多维表格 URL**（直接粘贴完整链接，App 自动解析出 App Token 和 Table ID）
    - URL 格式：`https://xxx.feishu.cn/base/{app_token}?table={table_id}`
    - 用户也可手动填写 App Token + Table ID
  - 认证方式：**优先 Personal Access Token**，备选自建应用（App ID + App Secret）
- **测试连接**：配置完成后可一键测试，验证认证和表格访问是否正常，成功时显示表格名称和记录总数
- 精准读取指定页签中**标记为「允许发布」、「发布失败」或「发布中」**的行数据
  - 「发布中」状态纳入是为了处理孤儿任务（App 异常退出导致状态卡住）

### 2.2 飞书表格字段规范（固定列名）

使用方需按以下固定列名建表，App 按列名直接读取（10 列必须 + 1 列可选 = 共 11 列）：

| 列名 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 抖音账号 | 文本 | 是 | 抖音号，如 dyfx750s5c44 |
| 抖音名称 | 文本 | 否 | 抖音昵称，便于识别账号（可选列，不影响功能） |
| 作品素材 | 附件 | 是 | 图片或视频文件（见下方素材规则） |
| 作品标题 | 文本 | 否 | 图文作品的标题（视频作品无独立标题字段，此列留空即可） |
| 作品文案 | 文本 | 是 | 发布时的描述文案（视频和图文通用） |
| 话题标签 | 文本 | 否 | 话题关键词，支持逗号分隔（如：`美食,探店,深圳`）或换行分隔（每行一个，可带 `#` 前缀如 `#女装`），App 自动解析并逐个输入到抖音话题选择器 |
| 音乐名称 | 文本 | 否 | 抖音背景音乐名称（如：`草莓不能 创作的原声`），App 通过 CDP 搜索并下载音乐，合并到视频后上传；为空则不加音乐 |
| 发布状态 | 单选 | 是 | 允许发布 / 发布中 / 已发布 / 发布失败 |
| 发布时间 | 日期时间 | 否 | App 回写，发布成功后自动填入实际发布时间 |
| 定时发布时间 | 日期时间 | 否 | 可选，需精确到分钟（如 2026-03-26 18:00），设置后按指定时间定时发布；为空则立即发布 |
| 失败原因 | 文本 | 否 | App 回写，发布失败时自动填入失败原因 |

### 2.3 素材类型规则

抖音创作者中心的**图文发布**和**视频发布**是两条完全不同的流程，App 自动识别：

| 附件内容 | 识别为 | 发布路径 | 说明 |
|---------|--------|---------|------|
| 仅图片（1~N 张） | 图文作品 | 图文发布入口 | 支持多图，按附件顺序排列 |
| 仅视频（1 个） | 视频作品 | 视频发布入口 | 只取第一个视频文件 |
| 图片 + 视频混合 | **不合法** | 跳过并标记失败 | 失败原因写入「素材类型混合，请检查」 |
| 多个视频 | **不合法** | 跳过并标记失败 | 失败原因写入「不支持多视频，请拆分为多行」 |
| 无附件 | **不合法** | 跳过并标记失败 | 失败原因写入「缺少作品素材」 |

支持的文件格式：
- **图片**：jpg、jpeg、png、webp
- **视频**：mp4、mov
- **单个素材大小限制**：视频不超过 4GB，图片不超过 20MB

**视频封面**：
- 抖音可能要求发布前设置封面（提示"请设置封面后再发布"）
- 自动化流程：打开封面选择弹窗 → 选择系统推荐的第一个封面 → 点击确认
- 如未来需要自定义封面，可扩展增加「封面图」列

**抖音平台限制（需知悉）**：
- 图文作品最多支持约 **20 张图片**，超出部分可能被抖音截断
- 视频时长限制取决于账号等级（普通账号 15min，部分创作者 60min+）
- 需要**创作者中心权限**才能通过 Web 端发布（部分新号或未开通账号无权限）
- 发布频率不宜过高，建议单账号每日不超过 10~20 条

### 2.4 多抖音账号登录管理

- 通过弹窗中的 **WKWebView 加载抖音创作者中心页面**，用户扫码登录
- 登录成功后从 WKWebView 的 HTTPCookieStore 和 DOM 中**自动提取 Cookie 和用户信息**（昵称、头像、抖音号）
- **账号匹配机制**：登录成功后通过用户信息接口获取该账号的抖音号，与飞书表格中的「抖音账号」列进行匹配
- 本地文件加密存储多账号独立 Cookie（存于 `~/Library/Application Support/com.menggang.douyin-uploader/secrets/`，base64 编码，避免系统 Keychain 弹密码框）
- **Cookie 过期检测**：
  - App 启动时 + 每次执行前主动检测所有已存账号的 Cookie 有效性
  - 检测方式：用 Cookie 请求用户信息接口，返回成功则有效
  - 过期的账号在账号管理页标记为「已过期」，提示重新扫码
- **账号管理页展示**：

| 阶段 | 行为 |

- 登录成功后弹窗自动关闭，账号列表刷新

#### 2.5.3 暂停与停止

- 按钮切换为「继续」，点击后从下一条任务恢复
- 暂停期间 App 保持运行状态

**停止**：
- 当前任务等待当前步骤完成，然后标记为「发布失败」，失败原因写入「用户手动停止」
- 已完成的任务：保持原状（成功/失败都已回写）
- 尚未开始的任务：保持原状（仍为「允许发布」）

### 2.6 自动发布执行（Headless）

- 使用 **Chrome for Testing**（固定版本 131.0.6778.204，首次运行自动下载）通过 **Chrome DevTools Protocol (CDP)** 控制浏览器
- 每个账号使用独立的 Chrome 用户数据目录（`chrome-profiles/{accountId}/`），实现 Cookie 隔离
- 通过 CDP 注入已保存的 Cookie → 导航到抖音创作者中心 → CDP 命令完成自动化操作
- **串行执行**：按账号分组 → 逐账号、逐任务顺序执行
- 单条任务流程：
  1. 校验定时发布时间（若已过期 → 标记失败，原因「定时发布时间已过期」）
  2. 校验素材类型合法性
  3. 飞书回写当前任务状态为「发布中」
  4. 从飞书下载素材到本地临时目录
  5. 启动 Chrome 进程（CDP 调试端口），连接 CDP 客户端，注入 Cookie，导航到抖音创作者中心上传页
  6. 通过 CDP `DOM.setFileInputFiles` 设置文件输入框的文件路径，触发上传
  7. 等待上传完成（设置超时：视频 10 分钟，图片 2 分钟）
  8. 填写标题（仅图文）、文案；话题标签处理：
     - 解析话题标签：支持逗号分隔、换行分隔，自动去除 `#` 前缀和空格
     - 在 `contenteditable` 编辑器中先输入文案，然后逐个输入话题标签
     - 每个标签输入流程：空格 → 逐字符输入 `#标签`（每字符间隔 200ms）→ 等 1 秒让搜索结果出现 → 回车选中第一个结果
     - 注意：描述编辑器是 `contenteditable` 富文本，需通过 CDP 键盘模拟输入（非 `value` 设置）
  9. **音乐融合**（如「音乐名称」列有值，仅视频作品）：
     - 通过 MusicDownloader 在抖音创作者中心的文章发布页搜索音乐：
       - 打开文章发布页 → 点击「选择音乐」→ 搜索音乐名称 → 点击搜索结果触发音频加载
       - 通过 CDP 网络拦截捕获音频文件 URL（`douyinstatic.com/obj/tos-cn-*`）→ 下载到本地
     - 通过 AudioVideoMerger（AVFoundation）将音乐与视频合并：
       - 背景音乐音量 30%，原声保持 100%
       - 音乐时长不足则循环，超出则截断到视频长度
     - 上传合并后的视频文件（而非在发布页面内选择音乐）
     - 如搜索无结果或下载失败，日志记录警告，跳过音乐，继续上传原始视频
  10. 视频作品：处理封面（选择系统推荐封面或等待自动截取）
  11. 如有定时发布时间，设置定时发布（点击"定时发布"单选按钮 → 点击日期输入框并用 `select()` 全选 → 直接键入时间字符串覆盖 → Enter 确认）；否则立即发布
  12. 点击发布按钮，等待发布结果确认（页面跳转到内容管理页 = 成功）
  13. 回写飞书：成功 → 「已发布」+ 发布时间 / 失败 → 「发布失败」+ 失败原因
  14. 清理本地临时素材文件

### 2.9 CSS 选择器管理

由于抖音创作者中心页面结构可能不定期变更，导致选择器失效：

- 选择器目前硬编码在 `CDPPublishService.swift` 中（通过 `cdp.evaluate()` 执行 JS 查询 DOM）
- 优先使用**文字内容匹配**（如查找 `textContent === '定时发布'` 的元素），class 名作辅助
- 发布失败且疑似选择器问题时，日志中输出详细的 DOM 状态信息，便于排查
- 预留：未来可抽取为独立配置文件以支持热更新（v2 考虑）

### 2.10 网络状态处理

## 五、技术方案

| 模块 | 技术选型 | 说明 |
|------|----------|------|
| App 框架 | Swift + SwiftUI | 纯原生，macOS 13+，Universal Binary |
| UI 布局 | NavigationSplitView | macOS 13+ 原生侧边栏+内容区 |
| 飞书 API | URLSession + async/await | PAT 优先，备选 tenant_access_token |
| 系统通知 | UNUserNotificationCenter | 执行完成后通知用户 |
| 抖音登录 | WKWebView 弹窗 | 弹窗中加载抖音创作者中心页面，用户扫码登录，自动提取 Cookie |
| 抖音发布 | Chrome for Testing + CDP 协议 | 自动下载 Chrome 131.0.6778.204，通过 CDP WebSocket 控制浏览器完成自动化发布 |
| 音乐融合 | AVFoundation | 通过 CDP 从抖音下载音乐文件，用 AVFoundation 合并到视频中再上传 |
| 数据存储 | 本地文件 + JSON | 凭证（Cookie/PAT/Secret）base64 编码存 `secrets/` 目录（避免系统 Keychain 弹密码框），非敏感配置和日志存 JSON |
| 依赖 | **零第三方依赖** | 全部使用系统框架 |

### 技术决策记录

| # | 决策 | 结论 | 原因 |
|---|------|------|------|
| 1 | macOS 最低版本 | macOS 13.0+ (Ventura) | NavigationSplitView 需 13+，覆盖 2017 年后所有 Mac |
| 2 | UI 框架 | SwiftUI | 开发效率高，macOS 13+ API 完善（NavigationSplitView 等） |
| 3 | 抖音发布方式 | Chrome for Testing + CDP 协议 | 比 WKWebView 更稳定，支持 `DOM.setFileInputFiles` 直接设置文件，无需用户手势；账号间通过独立用户数据目录隔离 |
| 4 | 飞书认证 | PAT 优先 + 自建应用备选 | PAT 最简单，自建应用作兜底 |
| 5 | 浏览器可见性 | headless（Chrome 默认不显示窗口） | 调试模式下可显示 Chrome 窗口便于排查 |
| 5b | 凭证存储 | 本地文件 base64 编码（非系统 Keychain） | 避免系统 Keychain 每次访问弹出密码输入框，存于 `secrets/` 目录 |
| 5c | 音乐实现 | 下载音乐 + AVFoundation 合并视频 | 比页面内选择音乐更可靠，避免抖音页面音乐选择器的复杂交互 |
| 6 | 表格列名 | 固定列名，使用方按规范建表 | 简化实现，避免字段映射的复杂度 |
| 7 | 执行策略 | 串行（逐账号逐任务） | 安全稳定，不易触发抖音风控 |
| 8 | 进度展示 | 进度条 + 实时日志 + 完成总结 | 用户需要全局进度和详细操作记录 |

## 六、边界与异常处理

| 场景 | 处理方式 |
|------|---------|
| 素材类型混合（图片+视频） | 跳过，标记「发布失败」，原因：素材类型混合 |
| 多个视频附件 | 跳过，标记「发布失败」，原因：不支持多视频 |
| 无素材附件 | 跳过，标记「发布失败」，原因：缺少作品素材 |
| 定时发布时间已过期 | 跳过，标记「发布失败」，原因：定时发布时间已过期 |
| Cookie 过期（执行中发现） | 标记当前任务「发布失败」，跳过该账号剩余任务，日志提示重新登录 |
| 素材下载失败 | 标记「发布失败」，原因：素材下载失败 |
| 上传超时（视频10min/图片2min） | 标记「发布失败」，原因：上传超时 |
| 飞书 API 异常 | 标记「发布失败」，原因：飞书接口异常 |
| 用户手动停止 | 当前任务等待当前步骤完成后标记失败，剩余任务保持原状 |
| 飞书回写失败 | 日志中记录警告，不影响后续任务执行 |
| 「发布中」孤儿任务（App 崩溃残留） | 纳入筛选，视为待重试任务 |
| 网络中断（执行中） | 当前任务标记失败，暂停队列，提示用户 |
| 网络不可用（执行前） | 禁止执行，提示检查网络 |
| 飞书记录超过 500 条 | 自动分页拉取，直到所有记录读取完毕 |
| 不支持的文件格式（后缀不在白名单内） | 跳过，标记「发布失败」，原因：不支持的文件格式（xxx） |
| 抖音号不匹配（登录账号与表格不一致） | 执行概览中标记该账号为「未匹配」，提示重新登录正确账号 |
| 磁盘空间不足 | 下载素材前检查可用空间，不足时标记失败，原因：磁盘空间不足 |
| 视频作品填了标题列 | 忽略标题列，只使用文案列（视频发布无独立标题） |
| 图文作品未填标题 | 正常执行，标题字段留空（非必填） |
| 文案中包含换行符 | 保留换行，传递到抖音文案输入框 |
| 话题标签含空格（如"美食 探店"） | 自动去除空格，生成 `#美食探店`（抖音话题不支持空格） |
| 话题标签带 `#` 前缀（如 `#女装`） | 自动去除 `#`，解析为纯标签名后重新加 `#` 输入 |
| 话题标签换行分隔（每行一个） | 按换行拆分，等同于逗号分隔 |
| 文案 + 话题总长度超过抖音限制（~1000字） | 日志警告，仍尝试发布（由抖音侧截断或报错后标记失败） |
| 飞书附件格式不在支持列表内（如 .gif .avi） | 同上：标记「发布失败」，原因：不支持的文件格式（.gif） |
| 账号无创作者中心权限 | 发布失败，原因：该账号无创作者中心权限（需在抖音端开通） |
| 图文附件超过 20 张 | 日志警告，仍尝试发布（由抖音侧处理） |
| 音乐搜索无结果 | 日志警告「未找到音乐：xxx」，跳过音乐融合，上传原始视频 |
| 音乐下载失败/超时 | 日志警告，跳过音乐融合，上传原始视频 |
| 视频+音乐合并失败 | 日志警告「合并失败」，跳过音乐融合，上传原始视频 |
| 音乐名称列为空 | 正常执行，直接上传原始视频（不执行音乐下载和合并） |

## 七、发布状态 — 状态机

```
                    ┌─────────────────────────┐
                    │                         ↓
  ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
  │ 允许发布  │──→│  发布中   │──→│  已发布   │   │ 发布失败  │
  └──────────┘   └──────────┘   └──────────┘   └──────────┘
                    │                              ↑
                    └──────────────────────────────┘
                                                   │
                    ┌──────────────────────────────┘
                    ↓
              (下次执行时自动纳入重试)
```

| 转换 | 触发条件 |
|------|---------|
| 允许发布 → 发布中 | 开始执行该任务 |
| 发布中 → 已发布 | 发布成功 |
| 发布中 → 发布失败 | 发布失败、超时、用户停止、网络中断等 |
| 发布失败 → 发布中 | 下次执行时自动重试 |
| 发布中（孤儿） → 发布中 | 下次执行时自动纳入（App 崩溃后恢复） |

**禁止的状态转换**：
- 已发布 → 任何状态（已发布为终态，不可变更）
- 手动改为「允许发布」除外（用户在飞书中手动修改，表示想重新发布）

## 八、防呆与并发控制

| 场景 | 处理方式 |
|------|---------|
| 执行中再次点击「执行」 | 按钮禁用（灰色），提示「正在执行中，请等待完成」 |
| 执行中切换侧边栏页面 | 允许切换，执行在后台继续，进度信息不丢失 |
| 执行中关闭 App | 弹出确认对话框「有任务正在执行，确认退出？」 |
| 二维码扫码超时（约5分钟） | 二维码失效后自动刷新，提示「二维码已过期，已自动刷新」 |
| 飞书表格缺少必要列 | 测试连接/读取任务时检测，提示缺少哪些列并给出建表规范链接 |
| 必填字段为空（文案/账号/素材） | 读取任务时校验，空字段任务标记为校验失败，不纳入执行 |
| 飞书表格数据在执行期间被他人修改 | 以读取时的快照为准执行，回写时以 record_id 精确更新（不影响其他字段） |
| 多实例运行（用户同时打开两个 App） | 不做限制，但可能导致重复发布；后续版本可考虑文件锁 |

## 九、数据安全

### 9.1 敏感数据分类与存储

| 数据 | 敏感等级 | 存储位置 | 说明 |
|------|---------|---------|------|
| 抖音 Cookie（sessionid 等） | 高 | `secrets/douyin.cookie.{uniqueId}` | base64 编码 JSON，按账号隔离 |
| 飞书 PAT | 高 | `secrets/pat_{configId}` | base64 编码 |
| 飞书 App Secret | 高 | `secrets/appSecret_{configId}` | base64 编码，不可明文存 JSON |
| 飞书 App ID | 低 | JSON 配置文件 | 非敏感，可明文 |
| 飞书 App Token / Table ID | 低 | JSON 配置文件 | 非敏感 |
| 配置名称等 | 低 | JSON 配置文件 | 非敏感 |
| 执行日志 | 中 | JSON 文件 | 需脱敏处理 |
| 临时下载的素材文件 | 中 | 系统临时目录 | 使用后立即删除 |

### 9.2 日志脱敏规则

日志文件可能被分享给他人用于排查问题，因此：
- Cookie 值仅显示前 4 位 + `***`（如 `sess****`）
- PAT / Token 仅显示前 4 位 + `***`
- 抖音账号正常显示（非敏感）
- 素材文件名正常显示
- 音乐名称正常显示（非敏感）

### 9.3 临时文件管理

- 素材下载到 `FileManager.default.temporaryDirectory/douyin_upload/` 子目录
- 每条任务执行完毕（无论成功失败）后立即删除该任务的临时文件
- App 启动时清理残留的临时文件（上次异常退出可能遗留）

### 9.4 凭证存储安全

- **不使用系统 Keychain**，改用本地文件存储（避免每次访问弹出系统密码输入框）
- 存储路径：`~/Library/Application Support/com.menggang.douyin-uploader/secrets/`
- 编码方式：base64 编码（简单混淆，非加密）
- 每个凭证对应一个独立文件，key 名即文件名
- 所有凭证操作封装在 `KeychainService` 统一管理（虽然名为 Keychain，实际为本地文件实现）

### 9.5 App Sandbox

- **不开启 App Sandbox**（不上架 Mac App Store）
- 原因：需要启动外部 Chrome 进程、访问本地文件系统，且本工具为内部使用，不需要 App Store 分发
- 如未来需上架 App Store，需要添加 `com.apple.security.network.client` 等 entitlement

## 十、合规风险提示

- 自动化发布可能违反抖音平台的《服务条款》和《创作者运营规范》
- 大批量自动化操作有触发风控或账号封禁的风险
- 建议：
  - 控制发布频率（已在设置中提供参数控制）
  - 模拟正常操作节奏（已有随机延迟策略）
  - 仅用于合法的内容运营场景
  - 了解并接受可能的账号风险

> 本工具为运营效率工具，使用者需自行承担操作风险。
